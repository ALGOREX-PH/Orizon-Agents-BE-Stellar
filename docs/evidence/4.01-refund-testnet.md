# 4.01 evidence — live partial-credit refund on testnet (BLO-29)

The SOW §6.1 **D3** artifact: _"a partial-refund tx on Stellar Expert
(testnet)."_ This is the acceptance criterion the spike could not satisfy from
CI — _"a real refund has landed on testnet; a design that has never moved money
is not a decision."_ It has now landed.

The mechanism is [ADR 0002](../decisions/0002-partial-credit-refund.md): the
settler funds a **platform credit** to the buyer over the asset SAC
(`transfer(settler → buyer)`) — never a clawback from the agent. Unit-tested in
`tests/test_refund_svc.py`; run live via `scripts/prototype_refund.py`.

## Honest note on the testnet asset

The testnet asset SAC (`CDLZFC3S…`) wraps the **native asset** — its on-chain
`name` and `symbol` both read `native`, `decimals: 7`. So this credit moved
**0.054 XLM**, denominated in the SAC's own unit. On mainnet the same SAC seam
wraps USDC; the code path (`refund_svc.execute_refund`) is identical and asset-
agnostic — it credits whatever the configured `asset_sac` holds. The demonstration
proves the money-moving mechanism, not a USDC-specific one.

No trustline step was required (native asset); both accounts were funded via
friendbot before the run.

## Reproduce

```
python scripts/prototype_refund.py --buyer <G...> --amount 0.054
```

with the testnet `STELLAR_SIGNING_KEY` set (the settler). A read-only preflight
(settler identity, SAC metadata, both balances) should precede any live run.
