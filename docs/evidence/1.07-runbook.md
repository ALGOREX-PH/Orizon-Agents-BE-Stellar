# 1.07 runbook — first external-wallet registration on testnet (BLO-17)

**Milestone 1 exit gate.** A chapter contributor — not a Blocksmith, not the lead
dev — registers an agent through the public testnet UI with their own
friendbot-funded wallet, and we capture the transaction hash as proof that a
permissionless external registration lands on-chain.

This page is written to be handed to the contributor and executed **without a
developer present**. If a developer has to step in, that is a **finding**
(record it in `1.07-friction-log.md`), not a quiet save.

---

## Preconditions

Do not start until all of these are true:

| # | Precondition | Owner | Notes |
|---|--------------|-------|-------|
| P1 | The public testnet URL is live and reachable | story 1.11 | The deployed `/app/register` page, not localhost. Confirm it loads in a normal browser first. |
| P2 | The contributor has a supported Stellar wallet | contributor | Freighter, xBull, Albedo, LOBSTR, or Hana. Any one is fine. |
| P3 | A friendbot-funded **testnet** account **not owned by the Blocksmiths** | contributor | Must be the contributor's own wallet. **Never** the lead dev's wallet, never a shared Blocksmiths key. Testnet only. |
| P4 | An observer is ready with the friction log open | observer | `1.07-friction-log.md`, filled **during** the run — not reconstructed after. |

**Why the wallet ownership rule matters:** the whole point of D1 is that a
*stranger* can register permissionlessly. A registration from a wallet we control
proves nothing. The registering key must belong to the chapter contributor.

---

## Steps

The contributor does these unaided. The observer watches and writes; the observer
does **not** coach.

1. **Install a wallet.** Add one of the supported wallets (Freighter / xBull /
   Albedo / LOBSTR / Hana) as a browser extension or app, and create/open an
   account. Set the network to **Testnet**.
2. **Fund from friendbot.** Copy the wallet's public key (`G…` address). Fund it
   on testnet via friendbot — either <https://friendbot.stellar.org> (paste the
   `G…` address) or the "Fund account with friendbot" button in the
   [Stellar Lab](https://lab.stellar.org). Confirm the account shows a balance.
3. **Open the register page.** Go to the public testnet URL and open
   **`/app/register`**.
4. **Register — unaided.** Fill the form and submit:
   - **Agent id** — `[A-Za-z0-9_]{1,32}` (letters, digits, underscore; 1–32
     chars). Pick something recognisable for the sprint, e.g. `blo17_ext_<name>`.
     Do **not** use an `agt_`-prefixed id (those are reserved for the 12 seeded
     agents).
   - **Name** — a human-readable label.
   - **Skills** — the agent's skill tags.
   - **Price** — in **USDC** (the form takes USDC; the backend converts to
     stroops/i128 for you — you do **not** type stroops).
   - Let the availability check settle on the id field (it fires on blur), then
     **Sign + Submit**. Approve the signature prompt in the wallet.
5. **Capture on success.** On success the page shows the **tx hash** and a
   **stellar.expert** link. Use the success card's **"Copy evidence"** action to
   grab the artifacts in one go, and record everything in the capture checklist
   below.

The agent should now appear in `GET /api/agents` with `"source": "onchain"` and
an `owner` field set to the registering `G…` address. (Seeded agents are
`"source": "seeded"` with `agt_` ids — the new one is neither.)

---

## Capture checklist

Record all of these at the moment of the run (they go into
`1.07-evidence-index.md`):

- [ ] **Tx hash** — the transaction hash shown on the success card.
- [ ] **Wallet address** — the registering `G…` public key.
- [ ] **Agent id** — exactly as entered.
- [ ] **stellar.expert (tx) link** —
      `https://stellar.expert/explorer/testnet/tx/<hash>`
- [ ] **stellar.expert (account) link** —
      `https://stellar.expert/explorer/testnet/account/<G…>`
- [ ] **Timestamp** — ISO 8601, when the tx landed.
- [ ] **Wallet software used** — which wallet, and version if visible.

---

## Verification

Two paths, both valid — use whichever fits the reviewer.

**Technical path (script):** run the verification script against the captured
hash and id:

```bash
python scripts/verify_registration.py \
  --tx <hash> \
  --agent <agent_id> \
  --api-base <public testnet api base>   # optional: adds the marketplace on-chain-listing check
```

It prints a **PASS/FAIL** evidence report cross-checked from Horizon (the tx
exists, succeeded, and its source account matches the owner) and from the backend
(`GET /api/agents` shows the id with `"source": "onchain"` and the expected
`owner`). Record the result in the evidence index (`Verified by script? Y/N`).

**Non-technical reviewer path (no tools):** just open the **stellar.expert (tx)
link** in a browser. A successful transaction on **testnet** with the
registering account as source is the proof. No script, no wallet, no code.

---

## Rules reminder

- **Unaided means unaided.** If the contributor has to be talked through a step,
  log it as a finding with a severity — do not help them and then mark the step
  passed.
- **Friendbot only.** Fund on testnet from friendbot. No mainnet, no real funds.
- **No cleanup.** Do **not** delist or remove the test agent afterwards. It stays
  registered on testnet for the duration of the sprint as standing evidence.
- **Not a Blocksmiths wallet.** The registering key belongs to the chapter
  contributor, never the lead dev or a shared team key.
- **Capture live.** Evidence and friction are recorded during the run, not
  reconstructed later.
- **File bugs.** Any defect gets a **Bug** issue in Linear, linked to the story
  whose acceptance criterion it violates.
